## 在 Mac 上从头装时发现并修掉的（2026-11-16）

之前所有测试都在 Linux 的开发机上跑。第一次在 Mac 上照 README 装，476 项单测里有 77 项失败，原因两个：

- 文件存储的锁用的是 `flock` 命令，macOS 不自带。所以在 Mac 上存文件、交付文件都会失败。现在 macOS 上改成打开锁文件时由系统加锁（`O_EXLOCK`），进程退出锁自动释放；Linux 的做法不变。加了一项测试：同一个目录上的两个文件存储不能同时拿到锁。
- macOS 的临时目录在一个符号链接后面，文件存储拒绝这样的根目录。这只影响测试：`npm test` 现在先把临时目录换成真实路径（`test/setup.mjs`）。

修完后在同一台 Mac 上重新克隆、重跑，全部通过。

接着在这台 Mac 上起了一个临时实例，用真模型（DeepSeek V4.1 Flash）走了一遍：

- 通过接口连写三个项目文件，都成功，锁文件和三个存储对象都在磁盘上。
- 说一句「写一个文件 a.md，内容只有一行：一」：10 秒内项目助理开出任务，20 秒内执行者写出文件、勾完两项清单、交到待验收。
- 再说一句把它交付到共享文件：10 秒内 a.md 出现在项目的共享文件里，由任务发布。
- 页面上项目、任务和状态都对，没有报错。都是单次实测。

## 量过的数字

都是单次实测，条件写在后面，不代表一般情况。

- 一句话到开出两个任务：14 秒（隔离实例，DeepSeek V4.1 Flash）。
- 「请求修改」到第 2 版交付：1 分 48 秒（同一次）。
- 一次失败的例子：执行者为了给网页截图，和无头浏览器较劲 11 分钟、约 120 万 token。这是模型和环境的问题，没有修。

- 线上实例自己定时跑的「夜里想一轮」：每天 01:00（北京时间），上一次在新提示词上线之前，下一次是 11 月 17 日 01:00。新提示词在隔离实例里跑过三次，又用线上数据的副本空跑过一次。
