# 一个真正好的 agent 产品，不需要 agent 这层抽象
> DS-buddy 今天开源。这篇文章记录做它的过程里，我对多 agent 的看法是怎么变的，包括走错的地方。

Hi 大家～

DS-buddy 是 DeepSeek Harness 的一个插件。你说一句目标，它拆成几个任务去做，做完交到你面前。

做它的起因很简单。同时用好几个 agent 干活的时候，我大部分时间在当胶水：给这个讲一遍背景，把那个的结论搬过来，盯着谁卡住了。真正该我做的事是想清楚方向，反而没时间做。

## 一开始，我也给 AI 排了岗位

早先的版本里，每个项目是一个群聊。群里有一个项目助理，它会按需要创建角色。每个角色有名字，有一两句人设，有自己的头像。我在群里 @ 它们干活。

这样做很自然。我们习惯了通过人来组织工作：谁负责什么，有事找谁。

到我回头去数的时候，12 个项目里一共建过 18 个角色。但我发现自己并不关心是哪个角色在干活。我关心的只是这件事做到哪了，用的是哪个模型。

后来我去看代码。一个角色实际贡献的只有三样东西：一个名字，一两句人设，一个默认模型。干活时的会话是按任务开的，不按角色开。也就是说，真正在干活的是这件事的上下文，加上一个模型。角色只是贴在上面的标签。

我把创建角色的功能删了。现在一个项目只有一个执行者，界面上显示的是它用的模型。

这件事改变了我的看法：管理 agent，其实就是管理上下文。

## 传话会走样

角色拿掉之后，还剩一处要传话：我把事情说给个人助理，它再转交给项目。

开源当天早上，我在一个全新安装的环境里从头走了一遍，顺手做了一次对照。同一句话，直接说给项目，16 秒后开出了两个任务，48 秒交回第一份。说给个人助理再转交，只开出一个合在一起的任务，11.6 分钟才交付。

原因是助理转交时重写了我的话，还补了几条我没说过的要求。下游把它们当成我的原话，照着做了。

现在转交只能引用我的原话，代码会核对这句话确实是我说的。助理想补充的另外标出来，不算我的要求。改完再测，转交之后半分钟内就开出了两个任务。

人和人传话会走样，agent 之间也一样。这也是 fork 多数时候比多 agent 好用的原因：fork 把上下文整份带过去，不经转述。

## 每件事一份自己的上下文

fork 也有代价。它什么都带，主对话越长，带的东西越多。长到一定程度只能压缩，细节就丢了。

所以我现在的做法是，上下文从一开始就按任务来组织，不指望它在一段对话里自己长出来。

我只讲三件事：要做什么，上下文在哪，标准是什么。AI 把它拆成任务，每个任务带一份自己的记录：目标，我的原话，怎么算完成，做到哪了。可以粗略理解成一份 goal 文件。

要长期维护的是这份记录。执行它的 agent 是临时的。默认是 DeepSeek Harness 里的一个会话，也可以在任务里换成 Claude Code。换了之后，接手的拿到的还是同一份记录。

每次启动时上下文怎么拼、缓存怎么用才省 token，我还没想透，不确定现在的做法是不是最好的。但这些不该是用户要操心的细节。

## 上下文得自己进来

做到这里，任务是 AI 拆的了，背景却还得我来喂：复制一段群聊，贴一个文件，讲一遍昨天做到哪。

所以我加了上下文的收集。屏幕上在做的事每分钟读一次，飞书消息每两分钟读一次。每 10 分钟整理成一条时间线，认得出属于哪个项目的就归过去。电脑里的文件，它需要时去读。全部只读，随时能关。

自动收集不是新鲜事。Screenpipe、AirJelly、Littlebird 和 Codex 里的 Computer History 都在做。DS-buddy 读屏幕用的就是 Screenpipe。我想多走的一步，是让这些上下文接到做事上。夜里它把这一天过一遍，早上最多留三张卡，告诉我有什么可以做、有什么值得看。

## 别家的做法

Multica 和 Raft 把 agent 当队友，用工单和群聊把协作组织起来。它们底层的设计很好，我借鉴了不少，比如每件事有一份长期的记录，结果落在大家都看得到的地方。Claude Projects 让一个项目里的几段对话共用一份资料，但只能用 Claude 的模型。

我和 Multica、Raft 的分歧只有一处：我不想让人来管 agent。事情怎么拆，谁来做，带哪些背景，我希望是 AI 的事。

## 现在的样子，和还没做好的

现在打开 DS-buddy，你面对的只有项目、任务和一块叫「待你决定」的看板。看板分三栏：等你，进行中，今天完成。等你那一栏放的是需要你的：要你拍板的，等你验收的，出了错的。只有你点了验收，一件事才算完。我希望人只在这些地方开口，不用再搬运信息。

里面一直在的那个助理，默认叫 Tacit，取「默会」的意思。我希望它在你开口之前，就已经了解和这件事有关的背景。

还没做好的也不少：

- 任务是 AI 拆的，项目还得你说一句它才建。
- 时间线的整理不总是对，相邻的几段容易被写成同一件事。
- 换执行者只在一轮做完之后生效。Codex 能选，但还没验证到它跑完一个完整任务。
