# 一个真正好的 agent 产品，不需要 agent 这层抽象
> DS-buddy 今天开源。这是我做它时想明白的一件事。

Hi 大家～

agent 越来越能干，我却越来越忙。

忙的都是搬运。把这个对话里的结论贴给那个对话，给新开的 agent 再讲一遍背景，盯着谁跑完了、谁卡住了，最后把几份结果拼到一起。一天下来，我大部分时间在当胶水。真正该我做的事，想清楚方向、做出判断，反而没时间做。

这不只是我的感觉。今年 3 月，BCG 在《哈佛商业评论》上发过一份 1,488 人的[调查](https://hbr.org/2026/03/when-using-ai-leads-to-brain-fry)：要一直盯着 AI 干活的人更累，同时用的 AI 工具到了三个，自己感觉到的效率就见顶了。他们管这叫 AI brain fry。

所以做 AI 应用产品，我觉得排在最前面的问题只有一个：降低人和 AI 沟通要占的带宽。人说得越少越好，AI 还得把事办对。

顺着这个问题看，我不太认同现在多 agent 产品的组织方式。我的看法是：**管理 agent，就是管理 context。**一个真正好的 agent 产品，不需要把 agent 这一层摆到你面前。

**一个 agent 拆开看，是一部分上下文加一个模型。**各家做抽象都先走向了 agent，我觉得是因为我们习惯了通过人来组织上下文：谁负责什么，有事找谁。于是也给 AI 排了岗位，起了名字。可人和人差别很大，所以才要分工。agent 和 agent 之间的差别极小，同一个模型换一段说明，「设计师」就成了「工程师」。真正有差别的是背后的模型。

再想一步：同一个项目里开三个对话，和拉三个 agent 围着同一件事干活，区别在哪？我想了很久，觉得没有区别，都是三份上下文，后面各接一个模型。对话只是 agent 那一侧装上下文的办法，一条线，只往后加。人想事情不按对话想，一件任务也不该被一条对话框住。

**让 agent 互相传话，多数时候没有必要。**人和人传话会走样，agent 也一样，还要多付一轮成本。我自己就翻过车：早先的版本里，我对助理说了一句目标，它转交给干活的 agent 时，顺手补了几条我没说过的要求，下游当成我的原话照着做了。fork 多数时候比多 agent 好用，原因也在这里：fork 是把上下文整份带过去，没有转述，就没有走样。

**但 fork 不丢东西，也不减东西。**主对话越聊越长，每 fork 一次都背着全部历史。回头看，多 agent 真正有用的地方在另一头：它给每件事单独开了一份干净的上下文。把名字和角色拿掉，剩下的就是一种管理 context 的办法。

我想两头都要：每件事一份干净的上下文，里面的话又是原样的。这靠一路聊下去是长不出来的，得一开始就围着任务来设计。

往哪个方向搭？我觉得不该是让人来控制：建频道，拉群，@ 谁。**人只需要讲清楚三件事：要做什么，上下文在哪，标准是什么。**然后由 AI 把它拆成一个个任务，每个任务带一份上下文包。可以粗略理解成一份 goal 文件：目标，你的原话，怎么算完成，做到哪了。要长期维护的是它，有进展就更新，开工时注入。

至于那些临时干活的 agent，都是 tool：一个 runtime，状态很脆弱，断了、换了，把上下文包重新注入就好。每次启动是不是一个全新的 context，怎么围着缓存省 token，这些我还没想透，但都不该是用户感知得到的细节。

**这就是我做 DS-buddy 的出发点。**现在的多 agent 产品，我觉得暴露得太多了。Claude Projects 让一个项目里的几段对话共用一份资料，但只能用 Claude 的模型。Multica 用工单，Raft 用群聊，底层的抽象做得很好，我借鉴了不少。只是在它们那里，agent 还摆在最前面，一件事怎么拆、每件事带哪些背景，多半还是人来定。搭 context、做分工，对人来说本身就是费力的事，胶水的活只是换了个地方。

**要让 AI 接过这一层，它得先足够了解你。**所以 DS-buddy 里最重要的设计，是上下文的收集。屏幕上正在做的事，飞书里的消息，源源不断地进来，每 10 分钟整理成一条时间线，认得出属于哪个项目的就归过去；电脑里的文件，它需要时可以去读。全部只读，随时能关。

自动收集不是新鲜事。Screenpipe（DS-buddy 读屏幕用的就是它）、AirJelly、Littlebird，还有 Codex 里的 Computer History，都已经在做。我看下来，它们多半停在记住和能查到。从看到的上下文里提出一件事，拆开，做完，再回到你面前等你拍板，这一圈还得人自己来接。DS-buddy 想接上的是这一圈。

我觉得这会是以后的工作方式：人只在真正需要自己的地方开口，说喜好，说取舍，给出关键的那一下指引，不再当信息的搬运工。

里面那个一直在的助理，默认叫 Tacit，取「默会」的意思，心领神会。一个真正好的 buddy，应该在你开口之前，就已经了解和这件事有关的一切。到那时候，背后有几个 agent、各叫什么，你不需要知道。

DS-buddy 是 DeepSeek Harness 的一个开源插件，代码在 [GitHub](https://github.com/DKKD13/tacit-dsh)。它还很早，例如任务是 AI 拆的，项目还得你说一句它才建。想看产品长什么样、各家产品怎么比，在[长文](deep/)里。欢迎来试，哪里说不通，直接告诉我～
